# projects-page runbook

https://byronxlg.com/ - one card per live project in the fleet registry, with its 20-second
launch video, its blurb and whether it is up. It is the page Byron opens to see everything he
runs, and the list the GitHub profile README is rendered from. Tier 3: nothing here has to stay
alive, and nothing depends on it. "Live" means the URL returns 200 and serves the `index.html`
that `bin/fleet page` last committed. Every byte of it is generated by management (see
[CLAUDE.md](../CLAUDE.md)); this repo holds no source.

## Where it runs

GitHub Pages, user site for `byronxlg`, `build_type: legacy` from `main` at `/`, custom domain
`byronxlg.com` with HTTPS enforced (certificate renews to 2026-12-21). DNS is owned by
`byronxlg/pdw` `infra/main.tf`: four apex A records at GitHub's Pages addresses and `www` as a
CNAME to `byronxlg.github.io`. The `CNAME` file is written by the render, so the custom domain
survives a republish. Project sites under the same domain (`/solar-system/`, `/skillfold/`) are
published by their own repos, not by this one.

failing tick marks the project suspect and only the second one turns it red (G27, G35).

## Recovery

The probe is red, so the page is not what was committed here. In order:

1. `curl -sI https://byronxlg.com/` - not 200 means Pages, DNS or the certificate, not content.
   `gh api repos/byronxlg/byronxlg.github.io/pages` shows `status`, `cname`, `https_enforced`
   and the certificate state. A `cname` that has gone empty means a render pushed without the
   `CNAME` file: re-run `bin/fleet page --push` in management, which writes it every time.
2. `gh run list --repo byronxlg/byronxlg.github.io --limit 5` - a failed or missing
   `pages-build-deployment` is the deploy. Re-run it (`gh run rerun <id>`) or push an empty
   change by running `bin/fleet page --push` again.
3. Content differs but both are healthy: the push failed while the commit landed locally.
   `git -C ~/repos/byronxlg.github.io status` and `git log --oneline -3 origin/main..HEAD`;
   push it.
4. DNS: `dig +short byronxlg.com A` must be the four `185.199.10[8-11].153` addresses. They are
   Terraform in `byronxlg/pdw` `infra/main.tf` - fix there through the apply workflow, never by
   hand in Cloudflare.

Nothing here is restored by editing this repo. If the content is wrong rather than missing, the
registry or the template is wrong: fix it in management and let the next tick publish.
